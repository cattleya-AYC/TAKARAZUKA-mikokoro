# スタッフ用ツール群 README(当日運営・準備進行・名刺印刷・LINEテンプレート)

小林タカラヅカ倶楽部の「観劇会当日の仕事分担」「準備期間のタスク管理」「食事名刺(席札)印刷」「LINE返信テンプレート」をまとめたREADMEです。`entry-form.html`系・`gift-letter`系とはまた別のテーブル・別のフローで動いています。

---

## 1. 当日の仕事分担システム(staff-schedule-admin.html / staff-schedule-view.html)

| ファイル | 役割 | ログイン |
|---|---|---|
| `staff-schedule-admin.html` | まり管理者用。当日の仕事割り当て・お菓子当番連動・自動割り当て | 必要 |
| `staff-schedule-view.html` | スタッフ全員が見る、当日の時系列スケジュール表示 | 不要 |

### 1-1. 固定スタッフとチームペア

固定スタッフ6名(シニオリティ順):原田・水無瀬・西中・伊庭・岩本・太田。

楽屋口お菓子当番・金銭回収の固定ペア(`jenne-gift-form.html`と共通、`DUTY_PAIRS`):
- 原田 ⇔ 太田
- 伊庭 ⇔ 岩本
- 西中 ⇔ 水無瀬

### 1-2. お菓子当番から仕事を自動で振り分けるルール

`PAIR_AUTO_RULE`により、お菓子当番でない残り2チームに、まだ空欄の行だけ自動でペアをセットする。

- **teamA担当**:チケット抽選係、食事なしの参加者へチケット渡し(インフォ前)
- **teamB担当**:メッセージカード配布、チケット封入、撮影(食事中)
- お菓子当番チーム:メッセージ回収(手紙・メセカ回収/差し入れ代回収)、お金徴収(これは元から自動)

**教訓(2026年9月)**:「撮影(食事中)」のように複数人ペアで割り当てる仕事(`PAIRABLE_TASKS`)は、担当が偶然`DUTY_PAIRS`のどれかと完全一致すると、システムが「これは固定ペアの仕事だ」と誤判定し、集計や自動割り当てから除外されてしまうことがある。この挙動自体はチーム選択ドロップダウンの仕組み上必要だが、原因が分かりにくいので注意。

### 1-3. 担当回数タリー(集計)の除外ルール

画面上部の「担当回数」集計は、**「チケット引取り」「店支払い」の2つだけ**を除外してカウントする(2026年9月に変更。以前はテーブルリーダー・固定担当全般を除外していたが、この2つ以外は当日業務としてカウントすることになった)。この2つは準備期間の仕事の延長という位置づけのため。

🔀の自動割り当て(個別行・全体まとめて)も同じ除外ルールを使っている(`getExtraExcluded`・`currentEventCounts`共通)。

### 1-4. 「全員」タイプの仕事の自動除外

「飲み物カード設置」は「座席表の色分け」と同様、**チケット封入チームを自動で除外**して残り4人に割り当てる(`EXTRA_EXCLUDE_PACK_TASKS`)。🔀ボタンでもこの除外が反映される。

### 1-5. テンプレート読み込み時の注意

「この回のスケジュールを読み込む」ボタンは、**当番の自動同期行(`from_duty`)だけがある状態では上書き確認を出さない**ように修正済み(2026年9月)。以前は当番だけ入っている新規イベントでも「すでにスケジュールがあります」という紛らわしい確認が出ていた。

### 1-6. staff-schedule-view.html(スタッフ閲覧側)の内容

- **集合時間**:13時公演→11:15、11時公演→10:15を自動判定して一番上に表示。
- **お菓子担当バナー**:`event_duty`から当番を取得し、目立つ色のバナーで表示。「◯◯さん」表記、次のローテーション順の人も表示(`次回は◯◯さんの番です`)。金銭回収担当の名前は表示しない方針(2026年9月)。
- バナーの下に「📷 当日中に差し入れサイトへ、お菓子・領収書・のし紙付きの菓子箱の写真を登録してください」という指示文を常設。
- 各仕事は`time_label`から時刻を読み取り**時刻順に並び替えて表示**(登録順ではない)。同じ時刻の仕事は1つの時刻ブロックにまとめる。時刻が読み取れない仕事(テーブルリーダー等)は「随時」として最後に表示。
- メモ内の`{{食事あり人数}}`等のタグは、`registrations`から実際の人数を集計して**自動で数字に置き換えて表示**する(admin側はプレビューだけだったが、view側は実際に置換する)。
- 読み込み中表示は目立つよう大きく点滅させている(`📡 読み込み中‼️`)。

## 2. お菓子当番の自動ローテーション(jenne-gift-form.html)

- ローテーション順(11時/13時公演は関係なし、開催回ごとに1人ずつ進む):
  **水無瀬→伊庭→原田→西中→岩本→太田→(また水無瀬に戻る)**
- 当番が**まだ設定されていない回**を開くと、直近の過去回で最後に当番だった人を調べて次の人を自動提案する(`suggestNextDutyStaff`)。提案は「🔁ローテーション順の自動提案です」と表示され、手動で変更も可能。
- 提案はプルダウンに反映されるだけで、実際にDB(`event_duty`)へ保存されるのは、従来通り③の「差し入れ先を確定」ボタンを押したタイミング。
- すでに当番が設定済みの回では、自動提案では上書きしない。

## 3. 準備期間タスク管理(task-tracker.html / prep-schedule-view.html)

| ファイル | 役割 | ログイン |
|---|---|---|
| `task-tracker.html` | まり専用の「私用ダッシュボード」内の、準備タスク一覧・チェック管理 | 必要 |
| `prep-schedule-view.html` | スタッフ全員が見られる、準備タスクの進み具合の一覧表(閲覧専用) | 不要 |

### 3-1. タスク定義(TASK_DEFS)と担当者

両ファイルで同じ`TASK_DEFS`配列を持っている(**片方を直したらもう片方も直すこと**)。開催日(`event_date`)からの日数(オフセット)と担当者は以下の通り(2026年9月時点)。

| 何日前 | タスク | 担当 |
|---|---|---|
| 153日前 | 開催日程提案(3候補を伊庭が提示) | 伊庭 |
| 143日前 | 阪急交通社窓口(申し込み) | 水無瀬 |
| 136日前 | 決定内容アプリ入力(見積受領後) | 水無瀬 |
| 59日前 | 募集フォーム作成 | 西中 |
| 59日前 | LINE告知予約 | 西中 |
| 59日前 | 公式LINEへの問い合わせ対応(募集開始〜開催直前・随時) | 太田 |
| 59日前 | 申込状況確認・人数調整(募集開始後・随時) | 全員 |
| 55日前 | レストラン予約 | 太田 |
| 50日前 | メニュー確認と連絡 | 太田 |
| 49日前 | 食事メニュー登録フォーム作成 | 西中 |
| 48日前 | 食事参加者へメール送信(フォームURL案内) | 西中 |
| 42日前 | 食事集計チェック(未入力催促) | 原田 |
| 40日前 | 個別請求書をLINEで送る | 西中 |
| 30日前 | 入金確認 | 岩本 |
| 29日前 | 入金督促(入金締切の翌日) | 岩本 |
| 15日前 | 差し入れフォーム作成 | 西中 |
| 14日前 | 差し入れ協力お願いメール配信(参加者へお知らせ) | 西中 |
| 14日前 | 差し入れ募集開始(自動・Edge Function) | - |
| 14日前 | 阪急交通社への振り込み | 岩本 |
| 10日前 | チケットクーポン受け取り(振込直後に発送されるため) | 伊庭 |
| 3日前 | 名刺・席札作成 | 原田 |
| 3日前 | 配布時のチケット封筒準備 | 伊庭 |
| 当日 | レストラン支払い | 岩本 |
| 当日 | チケット受け取り | 伊庭 |
| 締切+1日 | 申込者へ可否連絡(LINE/メール) | まり |
| 開催後3日 | ホームページ更新 | 西中 |
| 前日(当番による自動) | お菓子購入(`event_duty`から当番を自動取得) | 当番の人 |

**教訓**:「開催日程提案」「阪急交通社窓口」「決定内容アプリ入力」は、実際の見積書の日付から逆算して決めた(2026年6月22日見積発行・11月5日開催の実例で136日前=見積受領、そこからさらに1週間前=申し込み、さらに10日前=伊庭が候補日提示、という実測値を採用)。**必ず逆算した通りの順番になっているか(開催日程提案 < 阪急交通社窓口 < 決定内容アプリ入力の日数の大小関係)を確認すること**。過去に日数を仮置きしすぎて順番が逆転していたことがある。

「差し入れ集計」は`gift-letter-list.html`が自動集計するため、タスクとしては削除済み(2026年9月)。

### 3-2. お菓子購入タスクの特殊な扱い

`TASK_DEFS`の固定担当とは別に、`event_duty`テーブルから**その回の当番を動的に取得**して「お菓子購入(前日)」というタスクを都度追加している。担当者は開催回ごとに変わる。

### 3-3. 可否連絡・申込状況確認の担当について

- 「申込者へ可否連絡」は**まり自身**が担当(原田さんではない。2026年9月に修正)。
- 「申込状況確認・人数調整」は原田さん一人の担当ではなく、**募集開始後にみんなで随時チェックする**もの。

## 4. 名刺(席札)印刷システム

| ファイル | 役割 | ログイン |
|---|---|---|
| `lunch-namecard.html` | まり管理者用。食事申込データから名刺プレビュー・手直し・背景デザインの登録 | 必要 |
| `lunch-namecard-staff-print.html` | 原田さん用。食事申込者を読み込み→登録済み背景を選択→印刷するだけのシンプル画面 | 不要 |

### 4-1. 背景デザインライブラリ方式(のし紙と同じ考え方)

- `namecard_backgrounds`テーブル(id, label, image_url, sort_order)に、まりさんが複数の背景デザインを事前登録する。
- スタッフ側(`lunch-namecard-staff-print.html`)は、登録済みの背景から選ぶだけ(「背景なし(白背景)」も選択可)。
- のし紙(`nashi_backgrounds`)と同じ発想で作っている。

### 4-2. 印刷の余り枠を白紙で埋める

18人分など10の倍数にならない人数の場合、A4最後の1枚に余りが出る。この余り枠は**選んだ背景だけ印刷し、文字は空欄のまま**にする(`.pnamecard.blank`)。手書きで追加記入できるようにするための仕様(2026年9月)。まりさん用・スタッフ用の両方の印刷ボタンに実装済み。

### 4-3. データの出どころ

名刺は`meal_orders`/`meal_order_items`(食事申込)から生成しており、のし紙(`jenne_gifts`系)とはデータ構造が異なるため、2つの印刷物を1つの仕組みに統合することはできない(差し入れ相手用の名刺を作りたい場合は、`gift_letter_submissions`ベースで別途新規に作る必要がある)。

## 5. LINE返信テンプレート(line-templates.html)

ログイン不要・DBを使わない単純な静的ページ。よくある場面の定型文を、`[お名前]`などのプレースホルダー付きでテキストエリアに表示し、「📋コピー」ボタンでクリップボードにコピーしてLINEに貼り付けられる。

2026年9月時点のテンプレート:
1. 定員調整のお願い(2枚→1枚)
2. 入金確認のお願い
3. メール未達の確認
4. 次回開催日の問い合わせ回答

テンプレートを追加・修正したい場合は、ファイル内の`TEMPLATES`配列に`{ title, scene, text }`を追加するだけでよい。
